Distance sampling

Distance sampling estimates the density of a single species (animals per km²) from camera-trap detections with measured distances and camera effort. It follows the camera-trap distance sampling (CTDS) approach implemented in the R Distance package.

Key requirements:

  • Species: Select a single species for each run. Density is estimated per species; pooled multi-species analysis is not supported.
  • Detection Distances: Detections must have distance values, typically from distance estimation on calibration and trap images.
  • Study Area: Enter the survey or stratum area in km² for which you wish to estiamte species count.
  • Camera Field Of View: Enter the horizontal field of view in degrees.
  • Camera Effort: Effort is operating time at each site divided by the snapshot interval (default 2 seconds). Sites with effort but no detections of the selected species are included in the analysis.
  • Time To Independence: Detections at the same site are thinned so burst photos closer together than this interval count as one independent event (default 30 minutes). Set to 0 to disable thinning.
  • Detection Function: Models are selected automatically using QAIC within each key-function family (uniform, half-normal, hazard-rate), then compared with χ²/df (chi2_select, Howe et al. 2019). If max truncation is not set, the maximum observed detection distance is used.

Optional settings:

  • Min / Max Truncation: Optional truncation distances in metres for the detection function.
  • Snapshot Interval: Seconds used to convert operating time into CTDS effort units (default 2). Change only if your study used a different interval.
  • Activity Multiplier: When enabled, temporal availability is estimated from detection times with the R activity package and passed to dht2 as a multiplier (Howe et al. 2017). The full calculation is in distance_sampling.R (see build_activity_multiplier()). This adjusts density for the proportion of camera operating time when animals were active and available for detection.
  • Camera Operating Hours Per Day: Hours per 24 h calendar day that cameras were recording (default 24). Scales the activity rate when cameras were not on continuously.
  • Activity Time Scale: Clock uses wall-clock detection timestamps. Solar converts timestamps to solar time of day using mean trap-site coordinates and a UTC offset (computed in TrapTagger, same approach as activity pattern analysis). This is separate from camera operating hours.

Data selection on the Datasets tab applies as for other R analyses: choose surveys and annotation sets, an optional date range, and sites on the Sites tab. For a single-survey estimate, select that survey rather than All.

Results include density, standard error, confidence interval, detection count (after independence thinning), site count, sample fraction, effective detection radius, the selected detection function model, QAIC tables, optional activity multiplier details, and a detection function plot. Reliable inference generally requires sufficient camera sites and independent detections; very few sites produce wide confidence intervals.

View the underlying R script with View R Script, or download the Distance flatfile CSV with Download CSV. When detections are available, the CSV export also includes thinned detection timestamps and a one-row activity params file (lat, lng, utc_offset_hours, timezone) for reproducing the activity multiplier in standalone R.

Standalone R example with solar-time activity (after sourcing distance_sampling.R): 

flatfile <- read.csv("..._Flatfile.csv")
times <- read.csv("..._Activity_Timestamps.csv")$timestamp
params <- read.csv("..._Activity_Params.csv")

avail <- build_activity_multiplier(
  times,
  params$lat,
  params$lng,
  camera_hours_per_day = 24,
  activity_time_mode = "solar",
  utc_offset_hours = params$utc_offset_hours
)

# Then pass avail$multipliers to dht2() when fitting density from flatfile.

Solar conversion uses solartime::solartime() with the UTC offset from TrapTagger (Python timezonefinder / pytz). No additional R timezone packages are required.

Click Generate Results to run the analysis in TrapTagger. The job may take several minutes; do not leave the page until it completes.

The analysis uses the R packages:

  • Distance: Detection function fitting and density estimation via dht2.
  • activity: Temporal availability estimation when the activity multiplier is enabled.
